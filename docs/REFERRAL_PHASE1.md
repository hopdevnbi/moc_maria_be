# Referral phase 1 — owner policy 2026-11-20

## Non-negotiable identity rule
Uncertain signals are advisory only. Shared browser UUID (+35), high referral velocity (+25), repeated trusted network (+25), and a phone verified in an earlier referral (+40) never reject registration, mark users as duplicates, withhold a reward, or change eligibility. Missing signals are omitted. Existing login contact uniqueness remains unchanged. OTP proves possession, not a unique physical person. Exactly one referral and one positive ledger credit per new account; self-referral cannot be recorded. Existing users cannot retrospectively attach attribution. The user-directed change supersedes the earlier risk-based hold/reject plan.

## Implemented
ReferralFoundation1795082400000: six private tables, RLS and revoked direct client grants, stable random 20-character referral codes backfilled for existing accounts and lazily issued for new/other roles; immutable attribution on customer registration, configurable 100 coin default, independent attribution/payout flags default off. User and Super Admin APIs are no-store and authenticated; only Super Admin + admin.portal may view/review risk and change settings. Review is acknowledgement only, not a fraud judgment or award action.
Trusted IP input only if REFERRAL_DIRECT_CLIENT_IP=1 in a verified direct topology, or exact REFERRAL_TRUSTED_PROXY_IPS peer with an ingress that overwrites X-Real-IP. Otherwise omit. Use separate REFERRAL_SIGNAL_SECRET (32+ characters) for domain-separated HMAC; no raw IP or device UUID stored. Daily velocity >10 and network >=3 prior registrations/hour are advisory observations. Browser/network hashes older than 30 days and OTP challenge records older than 2 days are removed in bounded hourly cleanup with a DB advisory lock. Phone proof hash retained with reward transaction for reconciliation; separate stable REFERRAL_IDENTITY_SECRET; never rotate blindly.

Phone verification adapter: Twilio Verify API, optional and not activated. Config: REFERRAL_TWILIO_VERIFY_SERVICE_SID, REFERRAL_TWILIO_API_KEY, REFERRAL_TWILIO_API_SECRET, REFERRAL_IDENTITY_SECRET. Configure via Kubernetes secret, never commit or log. Confirm provider country support, pricing, service Fraud Guard, approved egress and spend limits before enabling payout. Per account send budget 3/day, 60s resend cooldown, max 5 verification attempts/challenge, 10min expiry. Provider status approved and matching SID/phone/service/channel required; no arbitrary client/admin assertion. In one transaction, lock the referred and referrer rows, verify current phone, record proof, create referral_coin_ledger and credit existing staff_coin_wallets, set REWARDED, audit. Risk does not gate payout. No fake check-in, no work on existing balance. Reward amount snapshot at registration. A previously verified phone is advisory only; reward still once per distinct qualifying account. No real SMS or production QA fixtures.

## Remaining gates
Provider credentials and live OTP acceptance; stronger global SMS budget / provider fraud configuration, email verification, CAPTCHA, user history and notification, reviewed reversal process, QR and sharing enhancements, admin reports, Zalo OA/GMF/voluntary invite consent (real group URL and provider permissions required), ingress trust validation/integration. No automatic addition to Zalo group by phone. Do not turn on payout or promise uniqueness from one phone/device/IP. Deployment order: isolated integration + full quality + CI, verified backup, verify only expected migration, then immutable backend rollout, then frontend. Separate user-visible activation decision. No production flags changed.
